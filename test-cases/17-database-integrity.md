# 17 — Database & Data Integrity

Covers MySQL schema behavior under `ddl-auto=update`, entity constraints, cascades, and cross-table consistency. Reminder: `ddl-auto=update` evolves new columns automatically but does **not** alter existing ENUM columns when new enum values are added — those require a manual `ALTER TABLE`.

| ID | Scenario | Preconditions | Test Steps | Test Data | Expected Result | Priority | Automation |
|---|---|---|---|---|---|---|---|
| TC-DB-001 | Unique constraint — one open `JobWorkSession` per employee | Employee has an open session | 1) Attempt to insert/force a second open session for the same employee (bypass API, direct DB insert or race condition) | duplicate `(employee_id, open_flag=true)` | Unique constraint on `(employee_id, open_flag)` rejects it | P1 | High |
| TC-DB-002 | Unique constraint — one `JobDailySummary` per employee per day | — | 1) Attempt duplicate insert for same `(employee_id, work_date)` | duplicate row | Rejected by unique constraint | P1 | High |
| TC-DB-003 | Unique constraint — `User.email` | — | 1) Attempt to create two users with identical email | duplicate email | `DataIntegrityViolationException` → 409 "Database constraint violated" | P1 | High |
| TC-DB-004 | Unique constraint — ATS technical/final interview `token` | — | 1) Force two interviews to share a token (should never happen via normal generation) | — | Constraint prevents collision even under extremely unlikely random-generation clash | P3 | Medium |
| TC-DB-005 | Adding a new enum value requires manual migration | New `CorrectionReason` or `Role` value added in code without a corresponding `ALTER TABLE` on the DB enum column | 1) Deploy code with new enum constant 2) Attempt to persist a row using the new value against an un-migrated DB | new enum constant | Insert fails at the DB layer (enum column doesn't accept the new value) until a manual `ALTER TABLE ...
